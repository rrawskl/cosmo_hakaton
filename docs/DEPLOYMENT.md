# Развёртывание

1. Подготовить хост с Docker Compose и исходящим HTTPS к разрешённым поставщикам.
2. Скопировать репозиторий, создать `.env` по примеру. Установить собственный
   `POSTGRES_PASSWORD`, ключ NASA и доступ Space-Track локально.
3. `docker compose up --build -d`; проверить `/health`, затем интерфейс.
4. Опубликовать frontend через HTTPS reverse proxy на выбранном домене.
   Backend, БД и `/admin/*` оставить недоступными извне.
5. Настроить ограничение запросов на proxy, доступ жюри и резервное копирование
   PostgreSQL. В локальном примере порты привязаны только к loopback.
6. Проверить текущий расчёт, исторический replay, сохранение, JSON и PDF.

Домен/хостинг пользователь пока не указал; внешняя публикация не выполнялась.
Не хранить production-пароли в compose.yaml; секреты передаются окружением.
SQLite — локальный режим разработки, PostgreSQL — compose/production.
Для диагностики использовать один backend worker: блокировки обновлений и
rate limit находятся в памяти процесса. Перед горизонтальным масштабированием
нужен общий lock/limiter и отдельный ingestion worker. Текущая схема этого не
заявляет. PostgreSQL snapshot хранит параметры каждого запроса независимо.

Для восстановления переносится PostgreSQL volume или его логический backup:
там находятся сырые записи, нормализация и сохранённые результаты. Временные
таблицы IERS/версии библиотек закреплены в requirements.txt. Выполненный расчёт
открывается по ID без запроса к внешним источникам.
