# Аудит расчётов и происхождения прогноза — 19 сентября 2026

Алгоритм 2.2.0. Проверены код backend, интерфейс сравнения, оба исходных PDF,
мастер-ТЗ и последующее требование заменить MMOD протонным мониторингом.
Производственные модули не используют fixtures, случайные измерения или
заранее заданные ответы для исторических дат. Синтетические входы используются
только в тестах границ и отказов. Сырые ответы сохраняются с SHA-256.

## Что является прогнозом

Внешний прогноз: NOAA 3-Day Forecast, Kp с шагом 3 часа и суточные вероятности
S1+, R1–R2, R3+. Собственный расчёт: пересечение этих интервалов с заданными
окнами, покрытие, условия внимания, сравнение кандидатов и геометрия МКС.
GOES — наблюдения, которые не экстраполируются в будущее.
Отдельной обученной модели прогноза протонного потока или дозы здесь нет.

## Формулы и проверенные границы

| Расчёт | Правило и смысл |
|---|---|
| Пересечение интервалов | max(0, min(b,d) − max(a,c)); перевод секунд в минуты, интервалы [a,b) |
| Длительность фактора | Мера объединения пересечений: дубли и одновременные сигналы внутри фактора не удваивают минуты |
| Покрытие Kp/R | Каждый из Kp, R1–R2, R3+ должен покрыть всё окно; пропуск не равен нулю |
| Покрытие протонов | Объединение пригодного S1-прогноза и пересечения наблюдённых интервалов ≥10/≥100 MeV; разрыв между точками не более 10 минут, один спутник |
| Шкала S | Пороги ≥10 MeV: 10, 100, 1000, 10000, 100000 pfu. Отдельный ≥100 MeV: 1 pfu |
| Тренд | Разность медиан двух 30-минутных окон; порог max(0.01 pfu, 20% первой медианы), минимум 4 точки в каждом, один спутник |
| Свежесть GOES | Возраст последней точки каждого канала не больше настроенного лимита, по умолчанию 30 минут |
| Орбита | SGP4/WGS72, TEME → Astropy ITRS → геодезические координаты WGS84; ISS NORAD 25544; возраст элементов ≤72 ч для всего интервала |
| Цилиндрическая тень | Для единичного направления Солнца s: r·s < 0 и ‖r − (r·s)s‖ < 6378.137 км |
| Сравнение | Лексикографически: наличие adverse, сумма adverse-минут факторов, сумма attention-минут факторов |

Сумма длительностей разных факторов — **фактор-минуты**, она может превышать
длительность окна. Это критерий ранжирования, не физическая доза,
не длительность единственного события и не вероятность общего риска.
Один протонный сигнал не включается повторно в Kp/R-фактор.

## Исправлено при аудите

- Два лучших кандидата из трёх больше не называются равенством всех окон:
  возвращаются tied_best, best_indices и объяснимые comparison_scores.
- Отсутствующий критический механизм считается неполнотой.
- Парсер отклоняет Kp вне 0–9, проценты вне 0–100, неправильные и повторные
  интервалы. Переход 21–00 UTC корректно означает конец следующих суток.
- Выпуск из будущего не считается доступным текущим прогнозом.
- Отменённые предупреждения не создают интервалы внимания.
- Поддержаны варианты Valid To, Valid Until и Now Valid Until.
- В сравнении видны диапазоны официальных чисел и временное разрешение.
- 60 секунд в геометрии обозначены как шаг дискретизации, а не доказанная
  погрешность физической модели тени.

## Что нельзя вывести из этих данных

Правила «Kp ≥5» и «ненулевая вероятность → внимание» — прозрачные правила
скрининга сервиса, а не утверждённые ограничения допуска ВКД. Для ≥50 MeV
дополнительный порог не придуман. Порог 72 ч для элементов и критерий тренда
также являются инженерными ограничениями реализации, не гарантией точности.

Суточная вероятность 55% не означает 55% вероятности события в каждом
шестичасовом окне. Пропорциональное пересчитывание по длительности или сложение
вероятностей без модели зависимости было бы необоснованным. Поэтому окна
могут оставаться равнозначными даже при разных числах внутри одних категорий.
Версия 2.2.0 не вводит скрытых весов для искусственного выбора победителя.

У активных факторов пока нет отдельного обоснованного правила adverse для
допуска ВКД; наличие этого значения в схеме не означает, что реализован NO-GO.
NOAA описывает опасность EVA для сильных S3–S5, но перевод удалённых измерений
в ограничения конкретного выхода требует эксплуатационной модели и эксперта.
Отказ источников, отсутствие прогноза или NORMAL сейчас не доказывают безопасность.

SGP4 и цилиндрическая тень являются вычислительными моделями по реальным
элементам, а не измеренной будущей траекторией. Манёвры, полутень и персональная
доза не моделируются. Два исторических эксперимента не подтверждают общую
прогностическую точность; для неё нужна независимая расширенная выборка.

## Дополнительная проверка UI и adverse (алгоритм 2.2.1)

Проверены создание факторов в `backend/app/analysis.py`, протонные правила
и ранжирование. `factor` инициализирует `adverse_minutes = 0`; активные правила
космической погоды и протонов создают состояния внимания, отсутствия триггеров
или недостатка данных, но не adverse. Освещённость не задаёт adverse.
Ранжирование поддерживает adverse в схеме, однако production-правила его
не порождают. Постоянный ноль — ожидаемое поведение модели (вариант B),
не ошибка объединения интервалов, секунд/минут или сериализации.

UI теперь скрывает нулевую строку adverse, когда ни статус, ни минуты,
ни интервалы результата не содержат adverse. Совместимость со снимками,
содержащими действительное adverse, сохранена. Минуты внимания и алгоритм
сравнения не изменены; новые пороги и формулы не вводились.

Блокировка выбора диапазона GOES была ошибкой frontend: наличие сохранённого
снимка отключало выбор и сетевую загрузку. Панель теперь независимо загружает
`/api/protons/history?range=6h|1d|3d|7d`, по умолчанию 6h. При смене диапазона
старый ответ скрывается, запрос отменяется; запоздавший ответ не заменяет новый.
Сохранённый расчёт, воспроизведение, JSON и PDF не изменены.

Историческая панель привязана к режиму и датам формы, а не только к последнему
результату. Проверяется весь интервал [начало, конец): он должен завершиться
и целиком лежать в rolling operational archive до 7 дней. При поддерживаемом
интервале отбираются только его реальные точки и заново вычисляются пики;
современные статус/тренд не переносятся в прошлое. Без точек — null и UNKNOWN,
без графика; за пределами архива запрос современных наблюдений не выполняется.
Произвольный исторический архив GOES отсутствует. Исторический прогноз S1 NCEI
остаётся отдельным входом backend; полный historical analysis по-прежнему
ограничен маем–июнем 2024. Просмотр наблюдений не расширяет этот контракт.

Локальная проверка изменений: 120 backend-тестов, 18 frontend-тестов,
production build (включая TypeScript) и 10 Playwright-тестов прошли.
Добавлены проверки диапазонов, границы 7 дней, недопустимого интервала,
фильтрации трёх каналов и пиков, отсутствия ложного NORMAL/нуля,
сохранённого текущего анализа и сохранения исторического S1 без GOES.
Playwright проверяет ошибки API, реальные актуальные данные NOAA,
отсутствие переполнения при ширинах 390–1920 px и снимки экранов.
Контролируемые UI fixtures используются только в тестах.
Backend выдал два предупреждения об устаревающих API тестовых зависимостей
и предупреждение о невозможности записи кеша pytest; тесты не падали.
Эти изменения пока проверены локально на Windows, а не новым запуском CI.

## Первичные источники, сверенные при аудите

- [NOAA Scales](https://www.swpc.noaa.gov/noaa-scales-explanation): значения шкал и различия S/G/R.
- [NOAA GOES Proton Flux](https://www.swpc.noaa.gov/products/goes-proton-flux): единицы, пороги, смысл предупреждений и времена действия.
- [NOAA 3-Day Forecast](https://www.swpc.noaa.gov/products/3-day-forecast): внешний прогноз, выпуск дважды в сутки.
- [Astropy: Earth satellites](https://docs.astropy.org/en/stable/coordinates/satellites.html): SGP4/TEME и преобразование координат.

Эта проверка подтверждает перечисленные свойства реализации; она не является
сертификацией системы планирования реальной ВКД.
